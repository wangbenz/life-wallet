## 1. 项目概述

### 项目名称

Life Wallet / 人生存钱罐 / 人生账本

### 核心理念

每个人每天都会“消耗 1 元人生”，但可以通过 AI 理解这一元是如何被使用的。

本产品不是记账工具，而是：

AI 人生理解系统（AI Life Understanding System）

### 核心问题

传统问题：

- 记录成本高
- 分类复杂
- 用户难以坚持
- 数据无法形成长期理解

### 产品目标

让用户只做一件事：

用自然语言描述一天发生的事情。

其余全部交给 AI：

- 理解
- 分类
- 结构化
- 长期分析
- 人生画像构建

## 2. 核心机制

### 2.1 人生余额机制（世界观）

```text
人生 = 固定总量
每天 = -1 元（不可逆）
```

特点：

- 不增加
- 不返还
- 不奖励
- 纯消耗模型

用于强化“时间不可逆”认知。

### 2.2 AI 记录机制

用户输入：

- 文字
- 语音（后续）

示例：

> 今天学了 Java 2 小时，练了英语口语 1 小时，晚上刷视频 2 小时

AI 自动生成：

- Activity（事件）
- 分类归因
- 时间分布
- 总结

用户只需确认（可选）。

### 2.3 核心原则

用户不应该做：

- 手动分类
- 选择标签体系
- 复杂结构整理

AI 负责：

- 分类
- 结构化
- 聚合
- 长期记忆
- 洞察生成

## 3. 分类体系设计

### 3.1 分类分层

#### 第一层：Life Dimension（固定）

系统级稳定维度：

- 成长
- 创造
- 关系
- 健康
- 生活
- 休闲
- 睡眠

用于长期统计，不变化。

#### 第二层：Domain（半动态）

AI 维护的领域：

- 代码
- 英语
- 金融
- AI
- 写作
- 运动

特点：

- 可扩展
- 可合并
- 可演化

#### 第三层：Topic（完全动态）

用户真实行为主题：

- Java
- Python
- 口语
- 雅思
- Spring Boot

特点：

- 不建固定表
- 仅作为语义标签
- 支持未来 embedding / 聚类

### 3.2 关键设计原则

- 用户不接触分类系统
- 不暴露三级结构
- 全部由 AI 自动生成
- 分类允许演化，尤其是 Domain

## 4. AI Agent 设计

### 4.1 Agent 职责

AI 不只是分类器，而是负责：

- 理解用户输入
- 提取 Activity
- 生成分类结构
- 计算时间分布
- 输出总结
- 形成长期记忆

### 4.2 输入输出流程

```text
用户自然语言
      ↓
LLM解析
      ↓
Activity抽取
      ↓
Dimension归因（固定）
      ↓
Domain归因（动态）
      ↓
Topic生成
      ↓
结构化记录
      ↓
用户确认（可选）
      ↓
入库
```

### 4.3 AI 输出结构（建议）

```json
{
  "activities": [
    {
      "title": "学习 Java",
      "duration": 120,
      "dimension": "成长",
      "domain": "代码",
      "topic": "Java"
    }
  ],
  "summary": "今天成长投入较多，学习为主"
}
```

## 8. 当前已确认 Decision

- Decision-001：每天固定扣除 1 元人生
- Decision-002：用户不进行任何手动分类
- Decision-003：AI 负责全部结构化理解与分类
- Decision-004：一级分类（Life Dimension）固定
- Decision-005：Domain 可演化（允许新增/调整）
- Decision-006：Topic 不作为数据库固定结构，仅语义标签
- Decision-007：用户输入必须使用自然语言（文字/语音）

## 13. Discovery Checklist 当前核对

### 13.1 目标用户

当前初步结论：

一二线城市上班族中，对生活需要数据化指标，并希望通过记录、分析和反馈来调整自己的人。

用户特征：

- 对生活质量、时间使用、成长投入有焦虑或追求。
- 能接受数据化反馈。
- 愿意通过低成本记录换取分析。
- 不一定愿意手动记账、打卡、分类。
- 更在意“我这段时间到底把人生花在哪里了”。

### 13.2 首次打开动机

“每天 1 元人生”不是核心功能本身，而是世界观入口和强记忆点。

首次进入建议流程：

```text
输入生日 + 预计寿命
  ↓
生成人生账户余额
  ↓
用户直观看到：人生账户不是无限的
  ↓
进入记录、分析和反馈的核心功能
```

这个入口的目标是制造一次认知冲击：用户意识到自己的人生账户余额有限，从而更愿意珍惜每天时间。

### 13.3 1 元人生的时间换算规则

```text
1 天 = 1 元人生
24 小时 = 1 元人生
1 小时 = 1/24 元人生
```

示例：

```text
本月英语学习 48 小时 = 2 元人生
本周运动 7 小时 ≈ 0.29 元人生
今天刷视频 3 小时 = 0.125 元人生
```

该规则将普通时间统计转化为“人生支出”反馈。

### 13.4 核心记录与反馈闭环

```text
人生余额冲击
  ↓
自然语言 / 语音记录一天
  ↓
AI Agent 自动分类
  ↓
换算为人生支出
  ↓
饼图展示 Life Dimension 占比
  ↓
个人支出排行展示具体支出方向
  ↓
日 / 周 / 月反馈帮助用户调整生活
```

### 13.5 每日 / 每周 / 每月统计

每日反馈：

- 展示今日 1 元人生如何被消耗。
- 使用 Life Dimension 饼图展示一级分类百分比。
- 使用 AI 一句话总结解释今日分布，而不是简单判断好坏。

每周反馈：

- 展示一周 Life Dimension 分布。
- 发现生活模式，例如成长投入、休闲占比、睡眠不足、关系投入偏少等。

每月反馈：

- 展示本月人生支出排行。
- 形成阶段性人生画像。
- 帮助用户识别值得保留或需要调整的行为模式。

### 13.6 个人支出排行

排行榜应优先做成“个人人生支出排行”，而不是用户之间的社交排名。

示例：

```text
本月人生支出 Top 5
1. 英语学习：2.0 元人生
2. 工作项目：1.6 元人生
3. 短视频休闲：1.2 元人生
4. 运动：0.5 元人生
5. 陪伴家人：0.4 元人生
```

个人支出排行回答的问题是：这段时间，我的人生主要花在了哪些事情上？

### 13.7 当前仍需验证

- 一二线城市上班族是否愿意持续输入自然语言记录？
- “生日 + 预计寿命 + 人生余额”是否足够吸引首次打开？
- 用户是否会觉得“人生支出”表达有启发，而不是制造焦虑？
- 日 / 周 / 月统计中，哪一种反馈对留存最关键？
- 饼图、支出排行、AI 总结三者的优先级如何排序？
