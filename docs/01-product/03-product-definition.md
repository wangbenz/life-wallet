# Product Definition

Status: Confirmed for H5 Validation
Last Updated: 2026-07-24
Owner: Human + Codex

## 产品定位

Life Wallet 是一个 Agent First 的 AI 人生理解产品：用户用自然语言记录生活，Agent 将记录转成可确认、可回看的时间片段与洞察。

一句话：

> 每天一句话，让 AI 帮你看见时间去了哪里。

产品直接使用天、小时和分钟作为时间尺度，不再引入“元人生 / 人生币”换算。Life Wallet 保留为品牌名，不代表金钱记账、积分或惩罚机制。

## 目标用户与问题

首批用户是一二线城市中愿意用数据理解生活、但不愿维护复杂时间工具的上班族。

他们的核心任务是：

> 用接近日常说话的成本记录生活，并得到值得回看的结构化理解。

备忘录容易记录但难以统计；专业时间工具可以统计但维护成本高。Life Wallet 要降低记录成本，同时保留长期理解的可能性。

## 核心闭环

```text
设置人生账户
→ 自然语言记录生活片段
→ Agent 提取活动、估算时长并分类
→ 用户预览、修改和确认
→ 保存已确认的时间片段
→ 基于真实记录生成近期洞察
```

只有用户确认后记录才生效；估算必须明确标记，不能伪装成精确事实。

除 Today 的一句话快速记录外，用户也可以进入 Life Agent 对话页，用自然语言查询、新增、修改或删除生活记录。Agent 是主要的自然语言操作入口，但不是唯一入口：涉及修改和删除时必须展示目标记录与变更差异，并在用户确认后执行；记录详情保留轻量手动操作作为可信兜底。

## 首版页面

### Today

- 展示按出生日期和预期寿命估算的剩余天数，并明确这只是时间参考。
- 首次入口同时解释每日记录、确认整理和长期洞察，避免把产品误解为寿命倒计时、人生计算器或金融账户。
- 支持当天、补记和同日多段自然语言记录。
- 首次开户使用聚焦流程，不把任意生日伪装成用户已选择的数据；创建成功后直接回到记录任务。
- 展示理解中状态、原句来源、结构化预览、修改与确认；分析完成后主动把用户带到确认区域。
- 预览确认操作不能被底部导航遮挡，活动数量少于原文片段时明确提示可能遗漏。
- 保存后提供“准确 / 部分准确 / 不准确”反馈。
- 右上角 Life Agent 入口进入独立对话页，不挤占快速记录主流程。
- Today 空首页说明记录会整理为活动、时长和感受，并在首次使用时解释 Life Agent 可查询或修改已保存记录，写操作仍需确认。

### Life Agent

- 支持通过 DeepSeek Agent 对话查询、新增、修改和删除本地生活记录。
- 查询只读取真实记录；找不到唯一目标时先追问，不猜测记录。
- 修改和删除先展示目标与变更差异，用户确认后才更新本地数据。
- 返回入口、快捷问题和输入提示跟随来源页面与当前目标记录，不用“今天”指代历史记录。
- 对话消息、目标记录和最多 20 条必要的近期记录字段会发送到后端并交给 DeepSeek；后端保存用户/Agent 对话和幂等结果，但不保存本轮记录快照。生日、预期寿命、反馈和无关本地数据不发送。
- Agent 返回的写操作只作为待确认建议，用户确认后才由前端调用受控后端 API 更新数据库记录。

### 输入方式

- 文字输入始终作为可靠主路径。
- Today 和 Life Agent 提供浏览器语音转文字；不支持或未授权时不阻断文字输入。
- 语音识别由浏览器能力提供，可能依赖系统在线服务；发送前必须允许用户检查和修改识别文字。

### Life

- “洞察”说明结论、数据依据和不确定性。
- “记录”按生活日回看和删除已确认记录。
- 低样本阶段弱化精确比例和稳定画像；历史卡片突出 Agent 修改，手动修正与删除作为次级操作。
- 数据不足时显示空状态，不生成假趋势、画像或成就。

### Me

- 设置生日与预期寿命。
- 导出和清除本地数据。
- 展示明确的已保存状态，使用面向普通用户的备份文案。
- 展示隐私边界并把体验反馈保存到测试服务，同时允许用户复制给体验邀请人。

## 首版范围

做：

- 人生账户。
- 文字自然语言记录，以及浏览器支持时的语音转文字。
- Activity 提取、时长估算、Life Dimension 分类。
- 预览确认、已记录时长反馈、今日总结。
- 基于真实记录的近期洞察和本地反馈。
- 基于真实 DeepSeek Tool Calling 的对话式记录查询，以及需确认的新增 / 修改 / 删除。

不做：

- 金钱记账、任务和日程管理。
- 分钟级计时和强制补齐 24 小时。
- 社交、排行榜、连续打卡、积分和成就。
- 心理诊断、治疗建议或羞耻式提醒。
- 没有数据依据的趋势、画像和 Dashboard。
- 完整微信小程序、复杂 Memory、RAG 和通用问答 Agent。

## 产品原则

1. 记录优先于统计：任何功能都不能增加不必要的记录成本。
2. 理解优先于精确：允许模糊表达和估算，但必须可修改。
3. Insight 高于 Dashboard：图表只作为证据，不是产品价值本身。
4. 用户不管理分类：Dimension / Domain / Topic 是系统结构。
5. 温和而不说教：总结事实、说明不确定性，避免制造焦虑。
6. 真实数据优先：数据不足就明确等待，不用假内容填满页面。
7. Agent 有边界：只处理与用户记录、目标和人生上下文相关的问题。

## 视觉原则

- 真实 H5 撑满视口，不绘制手机壳、系统状态栏或假时间。
- 风格为“清爽小程序 + 温和生活手账”：暖灰白、墨绿、低饱和品牌绿。
- 白色卡片只承载需要聚合或操作的内容，圆角、边框和阴影保持克制。
- 功能图标统一使用同一套 Lucide 线性图标；Agent 也使用同体系的温和对话符号，不单独绘制机器人。
- 关键日期输入使用统一的 H5 日历组件，支持月份与年份跳转，不依赖各操作系统样式不一的原生日期面板。
- 动画只解释状态变化和操作反馈，并支持 `prefers-reduced-motion`。
- 主要触控区域不小于 44px，手机视口不能横向溢出或遮挡底部操作。

## 验证标准

使用 5-10 个目标用户进行 7 个记录日验证，重点观察：

- 有多少用户完成 7 个记录日。
- 单次记录是否足够轻。
- 用户是否接受活动分类和时长估算。
- 用户是否能直接理解剩余天数、已记录时长和时间分布。
- Life 洞察是否让用户觉得值得再次打开。
- 反馈是否温和、有依据，而不是焦虑或说教。

真实 Agent 已以本地优先方式接入；验证结果决定是否继续部署后端、增加持久化或扩展 Agent 能力，不以页面数量作为成功标准。
