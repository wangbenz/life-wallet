# Life Ontology

Status: Active
Last Updated: 2026-07-15
Owner: Human + Codex

## 基础单位

```text
1 天 = 1 元人生
24 小时 = 1 元人生
活动人生币 = 活动分钟数 / 1440
```

人生币用于表达时间占用，不是货币、积分或价值评分。用户可以只记录有意义的片段，不需要补齐全天。

## Activity

Activity 是用户回看时有意义的一段行为或状态。第一版最小结构：

```json
{
  "title": "英语口语练习",
  "durationMinutes": 40,
  "dimension": "成长",
  "domain": "学习",
  "topic": "英语口语",
  "estimated": false
}
```

拆分原则：

- 目标、体验或领域明显不同的片段可以拆开。
- 普通细小动作不单独记录，除非用户明确表达它有意义。
- 情绪和状态可以作为记录上下文，不强行转成活动时长。
- 没有时长时允许估算，并设置 `estimated: true`。

## 生活日

记录时间不等于发生时间。系统优先尊重“今天、昨天晚上、凌晨、上午”等自然表达，将活动归入用户理解的生活日，而不是机械使用提交时间。

当前 H5 由用户选择补记日期；真实 Agent 后续再处理跨日语义。

## Life Dimension

首版固定维度：

| Dimension | 典型内容 |
|---|---|
| 创造 | 工作、产出、解决问题 |
| 成长 | 学习、阅读、练习 |
| 健康 | 运动、身体照顾、就医 |
| 关系 | 家人、朋友、伴侣和重要沟通 |
| 生活 | 家务、通勤、日常事务 |
| 休闲 | 电影、游戏、娱乐和放松 |
| 睡眠 | 睡觉、午休、熬夜和失眠 |

Dimension 是稳定统计层；Domain 和 Topic 用于表达更具体的个人语境。用户不需要配置这些字段。

## 状态与总结

- 状态词如“有点累、焦虑、开心、专注”作为 `stateDescription` 保存。
- 总结必须基于本次或已确认记录，不能推断未记录的完整生活。
- 数据不足时使用“从已记录片段看”等限定语。
- 不根据单次记录给用户贴人格、健康或生活方式标签。

## 不确定性与确认

- 明确时长直接使用；模糊或缺失时长可以估算。
- 所有估算在预览中可见且可编辑。
- 分类和时长只有用户确认后才成为记录事实。
- AI 无法合理理解时应请求补充，而不是编造活动。

## Memory 与 Agent 边界

当前 H5 只保存浏览器本地记录，不实现长期 Memory。

未来 Memory 只应保存用户可查看、修正和删除的事实或趋势。Agent 以理解、分类、估算、总结和温和反馈为主，不做心理诊断、危机判断、强制建议或与用户人生上下文无关的通用问答。
